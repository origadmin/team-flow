# Team Workflow 框架升级文档 — v3.7 → v4.0

> **升级日期**: 2026-04-23
> **核心变更**: 从"规则文档"升级为"流程引擎"，三层门禁强制执行

---

## 📌 为什么升级？

### 问题背景

在 v3.7 版本中，尽管有详细的流程规则，AI 仍然会：
- 跳过 Triage 直接处理需求
- 跳过设计阶段直接实现
- 跳过产出物报告声称完成

**根本原因**: 规则描述的是"应该做什么"，但无法强制"什么时候必须做"。

### 解决方案

v4.0 引入**三层门禁架构**，将规则变成**架构约束**：

```
规则（可绕过）→ 门禁（不可绕过）
```

---

## 🔄 版本对比

| 维度 | v3.7 | v4.0 |
|------|------|------|
| **入口控制** | Triage 可被绕过 | 入口门禁强制检查 |
| **阶段控制** | 可跳阶段 | 阶段门禁检查前置产出物 |
| **完成控制** | 可跳过产出物报告 | 完成门禁强制 Checklist |
| **文档性质** | 规则文档 | 流程引擎 |
| **执行原则** | 建议执行 | 禁止绕过 |

---

## 🏗️ 三层门禁架构

### Layer 1: 入口门禁 (Entry Gate)

**作用**: 确保所有需求都经过 Triage

```
用户输入 → [入口门禁] → task-pool 任务 OR T: 前缀
                                      ↓
                              不满足？→ 拒绝 + 引导
```

**执行时机**: 收到用户输入的第一时间

**违反后果**: AI 直接处理未分类需求 → 黑盒需求，无追踪

---

### Layer 2: 阶段门禁 (Phase Gate)

**作用**: 确保每个阶段都基于上一阶段的产出物

```
Phase 1 完成 → [阶段门禁检查] → Phase 2 产出物存在？
                                           ↓
                                    存在？→ 进入执行
                                    不存在？→ 拒绝 + 列出缺失
```

**执行时机**: 角色开始执行前

**违反后果**: 跳过设计直接实现 → 缺少必要文档

---

### Layer 3: 完成门禁 (DoD Gate)

**作用**: 确保完成前有完整的产出物

```
执行完成 → [完成门禁检查] → Deliverable Checklist 完整？
                                           ↓
                                    完整？→ 允许声称完成
                                    不完整？→ 拒绝 + 列出缺失
```

**执行时机**: 准备更新状态为 Done/Review 时

**违反后果**: 质量无保证，流程不可追溯

## 🔍 新旧流程对比

### Bugfix 流程

#### v3.7 (旧)

```
用户报告 Bug
    ↓
Dev 直接修复 → 声称完成 ❌
```

**问题**: 无 RCA，无 TEST_CASE，无产出物报告

#### v4.0 (新)

```
用户报告 Bug
    ↓
[入口门禁] → 检查 task-pool
    ↓
Triage 创建任务 + Bug 资产包
    ↓
[阶段门禁] → 检查前置产出物
    ↓
Dev 规范检查 → 产出规范检查报告
    ↓
[阶段门禁] → 检查规范检查报告
    ↓
Dev RCA → 产出 RCA.md
    ↓
[阶段门禁] → 检查 RCA.md
    ↓
Dev 修复 → 产出 TEST_CASE.md + 代码
    ↓
[完成门禁] → Checklist 全部通过
    ↓
更新 task-pool → Review
    ↓
用户确认 → Triage 归档 ✅
```

---

### Feature 流程

#### v3.7 (旧)

```
用户: T: 新功能
    ↓
AI 跳过 Triage？→ 直接实现 ❌
```

**问题**: 无资产包，无 task-pool，无追踪

#### v4.0 (新)

```
用户: T: 新功能
    ↓
[入口门禁] → T: 前缀检测
    ↓
Triage 分类 → 输出资产包预览
    ↓
用户确认 [A]
    ↓
Triage 物理创建资产包（5+1 文件）
    ↓
Triage 更新 task-pool（状态: Todo）
    ↓
PM 需求分析 → 填充 SPEC.md + AC.md
    ↓
[阶段门禁] → 检查 SPEC.md + AC.md
    ↓
Tech Lead 设计 → 填充 R1 + R2 + R3
    ↓
[阶段门禁] → 检查 R1 + R2 + R3
    ↓
Dev 实现 → 产出代码 + 测试
    ↓
[完成门禁] → Checklist 全部通过
    ↓
更新 task-pool → Review
    ↓
用户确认 → Triage 归档 ✅
```

## 📋 角色自检清单（新版）

每个角色执行前必须输出：

```markdown
【角色自检】{角色名称}

[Check: TaskPool √ | Phase Gate √ | Asset √]

┌─────────────────────────────────────────────────────────────────┐
│ 三层门禁检查                                                    │
├─────────────────────────────────────────────────────────────────┤
│ 【入口门禁】:                                                   │
│   - [ ] 任务存在于 task-pool                                   │
│   - [ ] 任务状态允许执行（Todo / Doing）                       │
│                                                                 │
│ 【阶段门禁】:                                                   │
│   - [ ] 当前阶段: {Phase X}                                    │
│   - [ ] 前置产出物检查:                                         │
│         - {产出物1}: ✅存在 / ❌缺失                           │
│         - {产出物2}: ✅存在 / ❌缺失                           │
│                                                                 │
│ 【本阶段产出物】:                                               │
│   - {产出物3}: 准备创建                                        │
│                                                                 │
│ → 门禁状态: ✅ 全部通过 / ⛔ 存在拦截                          │
└─────────────────────────────────────────────────────────────────┘
```

## 🚫 门禁拦截示例

### 入口门禁拦截

```
⛔ 入口门禁拦截

您的输入未经 Triage 分类：
  - T: 前缀: 否
  - task-pool 匹配: 否

可用选项：
  1. T: {需求描述}  ← 创建新任务
  2. T001  ← 执行已有任务
```

### 阶段门禁拦截

```
⛔ 阶段门禁拦截

任务 B001 当前处于 Phase 1 (规范检查)
您尝试进入 Phase 3 (修复)

前置产出物检查：
  ❌ Phase 2 (RCA) 产出物未完成
     - RCA.md: 缺失

禁止行为：
  - 跳过 RCA 阶段直接修复
  - "根因很清楚，先修再说"
```

### 完成门禁拦截

```
⛔ 完成门禁拦截

任务 B001 声称完成，但未通过完成门禁检查。

完成门禁检查结果：
  ❌ RCA.md 不存在
  ❌ TEST_CASE.md 不存在
  ✅ 代码修复已提交
  ✅ go vet 通过

禁止行为：
  - "代码修好了就行，文档后面补"
  - "用户急着上线，先这样"
```

## ✅ 升级验证

验证 Team Workflow 框架 v4.0 是否正确工作：

### 测试场景 1: 入口门禁

**操作**: 用户直接说"修复 xxx bug"（不带 T: 前缀）

**预期**: AI 拒绝处理，提示走 Triage 或使用 task-pool 任务 ID

### 测试场景 2: 阶段门禁

**操作**: Dev 尝试跳过 RCA 直接修复 Bug

**预期**: AI 拒绝，提示必须完成 RCA.md

### 测试场景 3: 完成门禁

**操作**: Dev 声称 Bug 修复完成，但没有 RCA.md 和 TEST_CASE.md

**预期**: AI 拒绝完成，列出缺失的产出物

## 📞 反馈与问题

如果发现 v4.0 框架存在问题：

1. **门禁误判**: 正常的输入被拦截 → 反馈具体场景
2. **门禁漏判**: 违规输入未被拦截 → 反馈具体场景
3. **流程不便**: 门禁合理但流程繁琐 → 讨论优化方案

**不欢迎的反馈**:
- "门禁太烦了，能不能绕过" ❌
- "这个需求很急，先做再说" ❌
