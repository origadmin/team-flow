### P0-2: Add YAML Frontmatter (team-flow-6x9.2)

**Goal**: Standard frontmatter for skill packaging and flow integration

**Frontmatter design**:
```yaml
---
name: team-flow
version: 2.3
description: |
  Multi-agent AI collaboration framework with beads-based task management.
  Provides Triage→TechLead→Dev→QA pipeline, three-layer gates, and 11 role definitions.
  Task management via flow task CLI.
  Path resolution via flow config paths --json.
  Compatible: Go backend + React/TypeScript frontend projects.
tools:
  - name: beads
    required: true
    commands: [create, update, close, list, show, ready, dep, dolt]
config:
  paths_source: "flow config paths --json"
  config_file: ".team/config.yaml"
  project_file: ".team/project.md"
evolution:
  v2: "beads migration, task management centralization"
  v3: "flow as center, tools/plugins/rules unified management"
---
```

**Key design decisions**:
- `description`: Functional (not trigger-oriented, since skill is always-on)
- `tools`: Declares beads dependency for `flow skill install` validation
- `config`: Declares where to find path resolution and project config
- `evolution`: Documents v2→v3 roadmap for maintainers

**Acceptance**:
1. SKILL.md has YAML frontmatter with all 6 sections
2. description is functional, not trigger-oriented
3. tools declares beads as required
4. config declares paths_source and config_file
5. evolution documents v2→v3 roadmap

**Files**: `team/v2/SKILL.md`

### P0-4: Path Resolution Mechanism (team-flow-6x9.4)

**Goal**: Eliminate path ambiguity via `flow config paths --json`

**Core principle**: Declare portable, resolve absolute, use absolute.

**Path anchor rules**:
| Prefix | Anchor | Example | Resolves to |
|--------|--------|---------|-------------|
| `_` | workspace root | `_docs/orig-cms/` | `{workspace}/_docs/orig-cms/` |
| other | project root | `docs/` | `{project}/docs/` |
| absolute | direct | `D:/xxx/` | `D:/xxx/` (not recommended) |
| not written | — | — | path not available |

**Path variables**:
| Variable | Source | Required |
|----------|--------|----------|
| `{WORKSPACE}` | flow config paths → workspace | yes |
| `{PROJECT}` | flow config paths → project | yes |
| `{DOCS_INTERNAL}` | flow config paths → docs_internal | no |
| `{DOCS_EXTERNAL}` | flow config paths → docs_external | no |
| `{BEADS_DB}` | flow config paths → beads_db | yes |
| `{TEAM_PATH}` | flow config paths → team_path | yes |

**AI startup sequence**:
1. Run `flow config paths --json`
2. Record all path variables to context
3. If docs_internal/docs_external not in output → not available, do not use
4. AI must never self-resolve relative paths, always use flow-resolved absolute paths

**SKILL.md section to add**:
```markdown
## Path Resolution

AI must run at startup:
\```bash
flow config paths --json
\```

Record output to context variables. Missing paths = not available.
AI must never self-resolve relative paths.
```

**Acceptance**:
1. SKILL.md has Path Resolution section
2. Documents `flow config paths --json` as single source of truth
3. Documents anchor rules
4. Lists all 6 path variables
5. States missing paths = not available

**Files**: `team/v2/SKILL.md`

**config.yaml template**:
```yaml

  name: {project-name}
  type: web-application

paths:
  docs_internal: _docs/{project-name}/
  docs_external: docs/

tools:
  beads:
    required: true
```

**project.md template update**:
```yaml
## Paths

project: {project-name}

# Internal docs (team-only, not public)
# _ prefix = relative to workspace root
# other = relative to project root
# Not written = this project has no internal docs
docs_internal: _docs/{project-name}/

# External docs (public, open-source documentation)
# Relative to project root
# Not written = this project has no external docs
docs_external: docs/

| abgen | (not written) | `docs/` |

**Acceptance**:
1. `templates/config.yaml` exists with version/project/paths/tools sections
