# Bug 报告模板

> 用于 Bug 修复任务的各个阶段产出物

---

## 01-norm-check.md - 规范检查报告

```markdown
# 规范检查报告

**Bug ID**: {BugID}
**检查者**: {角色}
**检查时间**: {YYYY-MM-DD HH:mm}

---

## 一、Bug 描述

| 项目 | 内容 |
|------|------|
| **用户报告** | {用户原始描述} |
| **复现步骤** | {如何复现} |
| **期望行为** | {用户期望} |
| **当前行为** | {实际行为} |

---

## 二、规范文档检查

| 规范文档 | 路径 | 状态 | 规范定义 | 与 Bug 关系 |
|---------|------|------|---------|------------|
| UI 标准 | `ui-standards.md` | ✅存在 / ❌不存在 | {规范定义} | 一致 / 冲突 / 无关 |
| 设计文档 | `ui-design/{feature}/DESIGN.md` | ✅存在 / ❌不存在 | {规范定义} | 一致 / 冲突 / 无关 |
| API 契约 | `R3_API_CONTRACT.md` | ✅存在 / ❌不存在 | {规范定义} | 一致 / 冲突 / 无关 |
| 状态机 | `R2_STATE_MACHINE.md` | ✅存在 / ❌不存在 | {规范定义} | 一致 / 冲突 / 无关 |
| 数据模型 | `R1_DATA_MODEL.md` | ✅存在 / ❌不存在 | {规范定义} | 一致 / 冲突 / 无关 |

---

## 三、检查结论

### 规范状态

| 情况 | 结论 |
|------|------|
| 规范存在且一致 | ✅ 真正的 Bug - 代码实现与规范不符 |
| 规范存在但冲突 | ⚠️ 规范冲突 - 需确认处理方式 |
| 规范不存在 | ❌ 规范缺失 - 需补充规范或基于代码推断 |

### 处理建议

| 选项 | 说明 |\n|------|------|
| [A] 直接修复 | 规范存在且一致，修复代码 |\n| [B] 确认后修复 | 规范冲突，需用户确认 |\n| [C] 补充规范 | 规范缺失，先补充规范 |\n| [D] 转需求 | 这是新需求，非 Bug |

---

## 四、下一步

- [ ] 用户确认处理方式
- [ ] 进入根因分析阶段
```
