# 阶段报告模板

> 所有任务类型的通用阶段报告模板
> 每个角色完成后产出自己的阶段报告，索引所有成果物和参考的标准文档

---

## 模板结构

```markdown
# {阶段名称}报告

**任务 ID**: {TaskID}
**任务类型**: feature / bugfix / docs / analyze
**报告角色**: {角色}
**报告时间**: {YYYY-MM-DD HH:mm}

---

## 一、阶段成果物

> 本次产出的所有文档/代码/测试

| 成果物 | 类型 | 路径 | 说明 |
|--------|------|------|------|
| {名称} | 文档/代码/测试 | {路径} | {说明} |

---

## 二、参考的标准文档

> 本次参考的标准文档，下一角色可据此了解规范

| 标准文档 | 类型 | 路径 | 参考内容 |
|---------|------|------|---------|
| UI 标准 | 规范 | `ui-standards.md` | 按钮高度 h10 |
| 设计文档 | 设计 | `ui-design/{feature}/DESIGN.md` | 按钮布局 |
| API 契约 | 规范 | `R3_API_CONTRACT.md` | 接口定义 |

---

|------|------|------|
| {决策} | {原因} | {影响} |

### 注意事项

```
{需要下一角色注意的事项}
```

## 四、下一阶段建议
```

## 核心原则

### 1. 每个阶段必须有阶段报告

> 不产出阶段报告，不算完成该阶段。

### 2. 阶段报告必须索引成果物

> 成果物可能很多，阶段报告作为索引，让下一角色快速找到需要的内容。

### 3. 阶段报告必须索引参考的标准文档

> 下一角色需要知道你参考了哪些标准，才能理解你的决策依据。

### 4. 阶段报告必须提供上下文

> 当前状态、关键决策、注意事项，让下一角色快速接手。

---

## AI 指令

### 角色完成阶段时

```
1. 产出阶段报告（按模板结构）
2. 索引所有成果物
3. 索引参考的标准文档
4. 提供上下文说明（当前状态、关键决策、注意事项）
5. 在 task-pool 产出物追踪表格中记录路径
```

### 角色接手时

```
1. 读取最新的阶段报告
2. 查看成果物索引，了解有哪些产出
3. 查看参考的标准文档，了解规范
4. 查看上下文说明，快速接手
```
