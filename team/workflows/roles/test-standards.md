## 12. UI 截图验证（设计 → 实现闭环）

### 12.1 验证依据

QA 进行 UI 验证时，必须持有两份文档：

| 文档 | 用途 | 路径 |
|------|------|------|
| **UI Design Document** | 验收基准（页面设计） | `{docs_internal}/requirements/{feature}/ui-design/DESIGN.md` |
| **ui-standards.md** | 规范依据（Design System） | `{TEAM_PATH}/workflows/roles/ui-standards.md` |

### 12.2 验证层级

| 层级 | 执行者 | 验证内容 | 方法 |
|------|--------|---------|------|
| **结构级** | AI + QA | 组件是否在正确区域，布局是否对齐 | HTML 快照对比 / Playwright screenshot diff |
| **规范级** | QA | 颜色/间距/高度/圆角是否符合 ui-standards.md | 抽取实际值，对照 Token 定义 |
| **功能级** | QA + Gherkin E2E | 交互行为是否按 DESIGN.md 执行 | Gherkin E2E 执行 |
| **视觉级** | Human | 字体渲染/配色美观/动效流畅 | 截图人工 Review |

### 12.3 UI 验证检查表

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 组件 ID 正确 | 对比 DESIGN.md 中引用的组件 ID | 所有组件均来自 ui-standards.md |
| 颜色使用 Token | DevTools 抽取色值 | 无硬编码色值，均来自 `--color-*` |
| 间距使用 Token | DevTools 测量 | 无自由值，均来自 `$spacing-*` |
| 输入框高度 | DevTools 测量 | 40px（统一规范） |
| 表格行高 | DevTools 测量 | 48px（统一规范） |
| 按钮状态 | 手动测试 Hover/Active/Disabled | 符合 ui-standards.md 规范 |
| 空状态 | 构造无数据场景 | 显示 `table-empty` 组件 |
| 加载状态 | 构造慢接口 | 显示 `loading-skeleton` |
| 错误提示 | 构造错误请求 | 显示 `message-error` |
| 响应式布局 | 浏览器 DevTools 模拟三端 | 三端布局均符合 DESIGN.md 响应式规则 |

### 12.4 Pixel Diff（CI 自动化）

对于频繁变更的页面，推荐 CI 使用 Playwright screenshot diff：

```bash
# 拍摄参考截图
npx playwright screenshot http://localhost:3000/page --viewport-size="1280,800" baseline.png

# 对比截图
npx playwright screenshot http://localhost:3000/page --viewport-size="1280,800" current.png

# 输出 diff
npx pixelmatch baseline.png current.png diff.png --threshold=0.3
```

| 偏差率 | 处理方式 |
|--------|---------|
| < 1% | 通过（允许渲染微小差异） |
| 1% - 5% | 警告，需 QA 确认 |
| > 5% | 失败，阻断合入，需 Human Review |

### 12.5 验证流程

```
Dev 合入代码
  → CI 运行 Playwright screenshot diff（结构级）
  → QA 执行 UI 验证检查表（规范级 + 功能级）
  → Human Review 截图（视觉级）
  → 通过 → 更新 baseline 截图 → 进入测试报告
  → 不通过 → 打回 Dev → 修复后重新验证
```

## 10. 测试用例模板（BDD 格式）

```markdown
## TC-{序号}: {测试用例标题}

**优先级**: P0/P1/P2
**测试类型**: 功能测试/边界测试/异常测试/性能测试
**前置条件**: [执行前的系统状态]

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 输入用户名: test@example.com | - |
| 2 | 输入密码: Test@123 | 密码显示为 * |
| 3 | 点击"登录"按钮 | 页面跳转到首页 |

### BDD 格式

```gherkin
Feature: 用户登录

  Scenario: 正确用户名和密码登录成功
    Given 用户在登录页面
    And   输入用户名 "test@example.com"
    And   输入密码 "Test@123"
    When  点击"登录"按钮
    Then  页面跳转到首页
    And   显示用户信息
```

### 测试数据

| 字段 | 值 | 说明 |
|------|-----|------|
| 用户名 | test@example.com | 已注册用户 |
| 密码 | Test@123 | 正确密码 |

### 边界值测试

| 测试场景 | 输入 | 预期结果 |
|---------|------|---------|
| 空用户名 | "" | 提示用户名必填 |
| 空密码 | "" | 提示密码必填 |
| 错误密码 | "wrong" | 提示密码错误 |
| SQL 注入 | "' or '1'='1" | 登录失败 |
```
