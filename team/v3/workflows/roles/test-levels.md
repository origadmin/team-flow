# 变更类型→测试级别映射与提测准入基线 — team-flow v2 (beads-native)

> **适用**: 所有代码变更的质量判定
> **关联**: devtestops.md（Step 3 变更类型判定 + Step 6 提测准入）

---

## 1. 变更类型判定规则

根据 git diff 和变更文件范围判定变更类型：

### 后端变更类型

| 变更类型 | 判定标准 |
|---------|---------|
| 纯逻辑调整 | 仅修改单文件/单函数内部逻辑，不涉及接口签名、跨模块调用或数据模型变更 |
| 接口改动 | 新增或修改 API 端点、请求/响应字段、错误码、鉴权方式 |
| 跨模块改动 | 变更涉及 2 个以上模块/包，或修改了共享数据模型、公共工具函数 |
| 核心链路改动 | 变更涉及登录/鉴权、下单/支付、任务提交/回调等核心业务入口 |
| 高风险改动 | 涉及数据迁移、架构重构、并发模型变更、第三方服务切换 |

### 前端变更类型

| 变更类型 | 判定标准 |
|---------|---------|
| 纯样式调整 | 仅修改 CSS/Tailwind 类名，不涉及逻辑变更 |
| 组件逻辑调整 | 修改组件内部状态、事件处理、条件渲染 |
| Hook 变更 | 新增或修改自定义 Hook 的参数、返回值、副作用 |
| API 调用变更 | 新增或修改 API 请求路径、参数、响应处理 |
| 页面/路由变更 | 新增页面、修改路由结构、修改路由守卫 |
| 全局状态变更 | 修改 AuthContext、TanStack Query 配置、全局 Provider |
| UI 组件库变更 | 修改 shadcn/ui 组件、Design Token、主题配置 |

## 2. 测试级别定义

### 单元测试（P0）

覆盖最小可测单元的正常/异常/边界路径。

**测试框架**：根据项目技术栈自动识别（Jest / pytest / Go test 等）

**覆盖要求**：
- 函数/方法的正常输入 → 正确输出
- 边界输入：空值、零值、超长、非法格式、特殊字符
- 异常路径：错误输入、非预期状态、字段缺失
- 状态流转：合法状态切换 + 非法状态处理

### 模块测试（P0）

组件/模块与直接依赖的联动行为。

**覆盖要求**：
- 组件 + Store/State 联动
- 组件 + 路由守卫联动
- Service + Repository 联动
- 中间件/拦截器行为验证

### 接口/API 测试（P1）

**覆盖要求**：
- 入参校验（必填、类型、格式、长度）
- 出参结构（字段完整性、类型正确性）
- 状态码和错误码
- 鉴权/权限（未登录、越权、角色差异）
- 幂等性（重复请求）
- 分页和过滤逻辑
- 兼容性（老字段不删、新字段有默认值）

**Mock 契约验证**（前端项目）：
- Mock 数据字段与 PRD 数据模型一致
- Mock 文件有 @prd 标注
- 调用处有 TODO[接入] 标注
- TypeScript 类型定义与 PRD 对齐

### 集成测试（P1）

**覆盖要求**：
- 跨模块调用链完整跑通
- 数据在模块间正确传递
- 事务一致性（DB 事务成功/失败/回滚）
- 缓存与 DB 一致性
- 消息队列生产者→消费者

### E2E 测试（P2）

**覆盖要求**：
- 从真实入口走完整业务流程
- 浏览器/客户端级别操作
- 跨页面/跨服务的状态流转
- 响应式布局验证

### 系统测试（P2）

**覆盖要求**：
- 跨模块业务流程闭环（如：注册→审核→登录→使用）
- 多角色交叉操作
- 数据隔离验证

### 安全测试（P1）

**覆盖要求**：
- XSS 防护（输入转义、输出编码）
- 注入防护（SQL 注入、命令注入）
- 权限绕过（URL 篡改、角色提权）
- 会话管理（持久化、过期、多标签同步）
- 敏感信息泄露（密码明文、日志、URL、响应体）

### 兼容性与回归测试（P2）

**覆盖要求**：
- 历史数据兼容（老数据不报错）
- 浏览器兼容（Chrome / Firefox / Safari）
- 移动端兼容
- 修复后回归不引入新问题

### 性能/基准测试（P2）

**覆盖要求**：
- 关键路径响应时间基线
- 并发压力下的稳定性
- 内存/CPU 使用无异常增长

## 3. 提测准入基线

### 后端提测准入

| 变更类型 | 必须完成 | 建议补充 | 不满足时 |
|---------|---------|---------|---------|
| 纯逻辑调整 | 单元 + 模块 + 基础回归 | 边界值 + 异常路径 | 🔴 不建议提测 |
| 接口改动 | + API 测试 + 兼容性检查 | 错误码 + 鉴权 | 🔴 不建议提测 |
| 跨模块改动 | + 集成测试 + 数据一致性 | 超时重试 | 🔴 不建议提测 |
| 核心链路改动 | + E2E + 专项测试 | 上线验证清单演练 | 🔴 不建议提测 |
| 高风险改动 | + 性能基准 + 回滚演练 + 灰度方案 | 异常场景演练 | 🔴 原则上不提测 |

### 前端提测准入

| 变更类型 | 必须完成 | 建议补充 | 不满足时 |
|---------|---------|---------|---------|
| 纯样式调整 | 视觉验证 + 响应式检查 | 截图对比 | 🟡 可提测 |
| 组件逻辑调整 | 单元测试 + 交互测试 | 边界值 + 异常路径 | 🔴 不建议提测 |
| Hook 变更 | Hook 单元测试 + 边界值 | 集成测试 | 🔴 不建议提测 |
| API 调用变更 | + MSW 集成测试 + CRUD 流程 | 错误处理 + 加载状态 | 🔴 不建议提测 |
| 页面/路由变更 | + 路由守卫测试 + 页面渲染测试 | E2E 流程 | 🔴 不建议提测 |
| 全局状态变更 | + 状态管理测试 + 跨组件集成 | E2E + 回归 | 🔴 不建议提测 |
| UI 组件库变更 | + 组件渲染测试 + a11y 测试 | 主题切换 + 响应式 | 🔴 不建议提测 |

## 4. 包管理器适配

测试命令必须根据项目环境使用对应的包管理器：

| 包管理器 | 测试命令 | 检测标志 |
|---------|---------|---------|
| Bun | `bun test` | `bun.lockb` |
| pnpm | `pnpm test` | `pnpm-lock.yaml` |
| yarn | `yarn test` | `yarn.lock` |
| npm | `npm test` | `package-lock.json` |
| Go | `go test ./...` | `go.mod` |
| Make | `make test` | `Makefile` 含 test target |

> ⚠️ 禁止跳过环境检测直接使用默认命令。先检测锁文件，再用对应命令。
