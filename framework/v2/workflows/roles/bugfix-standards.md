# Bug 修复规范 — v2 beads-native

> **版本**: v2.0 | **强制**: 数据流追踪 + 真实场景验证

---

## 强制数据流追踪

### 什么时候必须追踪

| Bug 类型 | 是否必须 |
|---------|---------|
| 涉及 API 调用/数据传递 | **必须** |
| 涉及权限/认证 | **必须** |
| 涉及状态流转 | **必须** |
| 涉及 UI 交互 | **必须** |
| 纯样式/配置问题 | 可跳过 |

### 数据流追踪步骤

```
Step 1: 定义起终点
  起点: 用户操作/API请求
  终点: 预期行为

Step 2: 列出每个环节
  输入 → 处理 → 输出

Step 3: 逐环节验证
  找到断点

Step 4: 记录断点
  位置 + 原因 + 根因类型

Step 5: 修复 + 验证完整链路
```

### RCA.md 模板

```markdown
## 数据流追踪 [v2]
### 数据流定义
- 起点: {用户操作}
- 终点: {预期行为}
### 环节清单
| # | 环节 | 输入 | 处理 | 输出 | 验证 |
|---|------|------|------|------|------|
### 断点分析
- 断点位置: 环节 #{N}
- 断点原因: {原因}
- 根因类型: {代码Bug/设计缺失}
```

| Bug 类型 | 最低验证 |
|---------|---------|
| 后端 API Bug | HTTP 请求验证 |
| 前端 API Bug | MSW mock + 组件测试 |

## R 迭代质量门禁

### R 迭代启动前必须回答

| 证明项 | 说明 |
|--------|------|
| 上一轮为什么失败 | 分析盲点 |
| 这一轮为什么能成功 | 策略差异 |
| 数据流断点已定位 | 展示追踪结果 |

### R 递增规则

| R 次数 | 策略升级 |
|--------|---------|
| R1 → R2 | 完整数据流追踪 |
| R4 → R5 | **强制暂停**：请用户确认方向 |

---

## beads R 迭代追踪

```bash
# R1 开始
mkdir -p {DOCS_INTERNAL}/reports/bugs/B{NNN}-R1/
bd update <id> --set-metadata doc_path="...R1/"

# R1 失败，R2
mkdir -p {DOCS_INTERNAL}/reports/bugs/B{NNN}-R2/
bd update <id> --add-label phase:analyze --set-metadata doc_path="...R2/"
```
