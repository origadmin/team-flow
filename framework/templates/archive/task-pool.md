# 任务池 (Active Tasks)

> 由 AI 在初始化时自动创建到 `.team/task-pool.md`
>
> **核心原则**：每个角色完成后产出自己的阶段报告，索引所有成果物和参考的标准文档，
> 并在 task-pool 中记录路径。后续角色通过阶段报告快速了解上下文。

## 状态定义

| 状态 | 含义 | 触发条件 | 设置权限 |
|------|------|---------|----------|
| `Todo` | 已创建，未开始 | 任务创建时 | **仅 Triage** |
| `Doing` | 执行中 | 角色认领任务 | 执行角色 |
| `Review` | 待用户确认 | 产出物完成 | 执行角色 |
| `Blocked` | 等待依赖任务 | 依赖任务未完成 | 执行角色 |

**状态流转**: `Todo` → `Doing` → `Review` → (用户确认) → `Archived`

**依赖任务流转**: `Todo` → `Blocked` → (依赖完成) → `Doing` → `Review` → `Archived`

**⚠️ 权限约束**:
- **Done 不作为公开状态**，用户确认后 Triage 直接归档
- **其他角色禁止设置 Archived**，防止跳过用户确认

## 多角色协作机制

> **核心原则**：协作请求必须结构化，协作任务必须有独立追踪，协作状态必须实时同步。

### 协作流程

```
角色A 发现需要协作
       ↓
创建协作子任务（自动生成启动文档）
       ↓
主任务进入阻塞状态
       ↓
在主任务启动文档更新协作请求 + 协作状态
       ↓
Triage 分配协作角色B
       ↓
角色B 执行子任务 → 更新协作状态
       ↓
角色B 完成 → 更新协作结果摘要
       ↓
主任务自动解除阻塞
       ↓
角色A 恢复工作 → 查看协作结果摘要
```

### 协作请求模板

> 协作请求必须包含完整信息，否则 Triage 拒绝分配

```markdown
## 协作请求

| 项目 | 内容 |
|------|------|
| **请求者** | {角色A} |
| **目标角色** | {角色B} |
| **协作内容** | {具体要做什么} |
| **输入** | {角色B 需要的输入，如文档、数据、接口} |
| **输出** | {角色B 需要产出的内容，格式要求} |
| **完成标准** | {如何判断完成，验收条件} |
| **优先级** | P0/P1/P2/P3 |
| **期望时间** | {期望完成时间，如 4h/1d/3d} |
| **参考文档** | {相关的启动文档/阶段报告路径} |
| **原因说明** | {为什么需要协作，无法自行完成的原因} |
```

### 协作状态追踪

> 实时追踪协作进展，不再被动等待

```markdown
## 协作状态

| 子任务ID | 目标角色 | 状态 | 当前进度 | 最后更新 |
|---------|---------|------|---------|----------|
| B001-1 | Dev-Backend | Doing | 规范检查完成 | 2026-04-22 15:30 |
```

**状态定义**：

| 状态 | 说明 |
|------|------|
| ⏳ 待分配 | 协作请求已提交，等待 Triage 分配 |
| 🔄 进行中 | 协作角色已接手，执行中 |
| ✅ 已完成 | 协作完成，结果已提交 |
| ❌ 已拒绝 | 协作角色无法完成，说明原因 |
| ⚠️ 超时 | 超过期望时间未完成 |

### 协作结果摘要

> 协作完成后，协作角色必须填写摘要，让请求方快速了解结果

```markdown
## 协作结果摘要

| 子任务ID | 目标角色 | 结果 | 关键产出 | 对主任务影响 |
|---------|---------|------|---------|-------------|
| B001-1 | Dev-Backend | ✅ 完成 | API 迁移到 v2 | 主任务可继续 |
```

### 协作超时机制

| 超时时间 | 处理方式 |
|---------|---------|
| 4 小时无响应 | Triage 发送提醒 |
| 24 小时无响应 | 升级为 P0，通知用户 |
| 3 天无响应 | 协作失败，主任务标记为 Blocked-Failed |

### 链式协作

> 协作角色B 也可以请求协作，形成链式协作

```
主任务 B001（角色A）
       ↓
协作子任务 B001-1（角色B）
       ↓
协作孙任务 B001-1-1（角色C）
```

**规则**：
- 链式协作深度不超过 3 层
- 每层都有独立的启动文档
- 任意层阻塞，上层自动阻塞
- 任意层完成，自动通知上层

## 产出物追踪机制

### 核心原则

> **每个角色完成后，必须产出阶段报告，索引成果物和参考的标准文档。**

### 阶段报告的作用

```
阶段报告 = 成果物索引 + 标准文档索引 + 上下文说明

作用：
1. 让下一角色快速了解有哪些产出物
2. 让下一角色知道参考了哪些标准
3. 让下一角色理解关键决策和注意事项
```

### 流程

```
角色接手任务
       ↓
读取最新的阶段报告
       ↓
查看成果物索引 → 了解有哪些产出
       ↓
查看标准文档索引 → 了解规范依据
       ↓
查看上下文说明 → 快速接手
       ↓
执行自己的工作
       ↓
产出自己的阶段报告
       ↓
在 task-pool 产出物追踪表格中记录路径
       ↓
更新任务状态，移交给下一角色
```

### 任务创建时（Triage）

```
1. 在活跃任务表格添加一行
2. 创建任务目录：{docs_internal}/tasks/{TaskID}/
3. 创建启动文档：00-INIT.md（使用 task-init-template.md）
4. 填写问题来源、里程碑关联
5. 初始化产出物索引（只有启动文档）
6. 设置当前状态
```

### 角色接手时

```
1. 读取启动文档：{docs_internal}/tasks/{TaskID}/00-INIT.md
2. 查看产出物索引，找到最新的阶段报告
3. 读取最新的阶段报告，了解上下文
4. 更新任务状态为 Doing
5. 开始执行自己的工作
```

### 角色完成时

```
1. 创建阶段报告：{序号}-{阶段名}.md
2. 更新启动文档：
   - 在产出物索引顶部插入新行
   - 更新当前状态
3. 如修改了规范文档：
   - 在文档变更记录中添加新行
4. 在 task-pool 更新关联文档列（指向最新的阶段报告）
5. 更新任务状态，移交给下一角色
```

### 发起协作请求时

```
1. 填写协作请求表格（必须完整：输入/输出/完成标准/优先级/期望时间）
2. 在启动文档 → 协作请求记录 添加新行
3. 创建协作子任务：
   - 在 task-pool 活跃任务表格添加子任务行
   - 创建子任务目录：{docs_internal}/tasks/{主任务ID}-{序号}/
   - 创建子任务启动文档
4. 更新主任务状态为 Blocked
5. 更新启动文档 → 协作状态追踪 表格
```

### 协作角色接手子任务时

```
1. 读取主任务启动文档，了解协作请求详情
2. 读取子任务启动文档
3. 更新主任务启动文档 → 协作状态追踪 表格（状态改为 进行中）
4. 开始执行协作任务
```

### 协作角色完成时

```
1. 创建子任务阶段报告
2. 更新子任务启动文档
3. 更新主任务启动文档：
   - 协作状态追踪 → 状态改为 已完成
   - 协作结果摘要 → 添加结果摘要
4. 主任务自动解除阻塞
5. 通知主任务负责人
```

### 协作超时时（Triage）

```
1. 4h 无响应：发送提醒给协作角色
2. 24h 无响应：升级为 P0，通知用户
3. 3d 无响应：标记协作失败，主任务状态改为 Blocked-Failed
```

### 任务关闭时（Triage）

```
1. 确认所有协作子任务已完成
2. 创建关闭报告：99-CLOSE.md
3. 更新启动文档：
   - 在产出物索引顶部插入关闭报告
   - 更新当前状态为 Closed
4. 用户确认后归档
```
