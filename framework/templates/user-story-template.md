# 用户故事模板

## 一、用户故事格式

```markdown
**作为** {用户角色}
```

## 三、示例

### 示例 1: 用户创建

```markdown
# 用户故事: 用户创建

## 基本信息

- **ID**: US-001
- **作为**: 系统管理员
- **我想要**: 创建新的用户账号
- **以便**: 为新员工提供系统访问权限
- **优先级**: Must
- **故事点**: 5

---

## 验收标准 (Acceptance Criteria)

### AC1: 成功创建用户
- **Given**: 管理员已登录系统
- **When**: 提交有效的用户信息（姓名、邮箱、角色）
- **Then**: 用户创建成功，返回用户 ID

### AC2: 邮箱重复时提示
- **Given**: 管理员已登录系统
- **And**: 系统中已存在该邮箱
- **When**: 提交用户信息
- **Then**: 提示"邮箱已存在"，不创建用户

### AC3: 邮箱格式错误时提示
- **Given**: 管理员已登录系统
- **When**: 提交无效的邮箱格式
- **Then**: 提示"邮箱格式不正确"，不创建用户

### AC4: 权限不足时拒绝
- **Given**: 普通用户已登录系统
- **When**: 尝试创建用户
- **Then**: 返回 403 Forbidden

---

## 业务规则

| 规则ID | 规则描述 |
|--------|---------|
| BR001 | 邮箱必须唯一 |
| BR002 | 邮箱格式必须正确 |
| BR003 | 角色必须是预定义值（admin/user/guest） |
| BR004 | 只有管理员可以创建用户 |

---

## 技术约束

| 约束类型 | 约束描述 |
|---------|---------|
| 性能 | 响应时间 < 200ms (P95) |
| 安全 | 需要管理员权限 |
| 数据 | 用户数据需加密存储 |

---

## 依赖关系

### 前置依赖
- US-000: 用户认证

### 后置依赖
- US-002: 用户查询
- US-003: 用户更新

---

## 备注

- 需要发送欢迎邮件给新用户
- 需要记录操作日志
```

### 示例 2: 用户登录

```markdown
# 用户故事: 用户登录

## 基本信息

- **ID**: US-000
- **作为**: 系统用户
- **我想要**: 使用邮箱和密码登录系统
- **以便**: 访问我有权限的功能
- **优先级**: Must
- **故事点**: 3

---

## 验收标准 (Acceptance Criteria)

### AC1: 成功登录
- **Given**: 用户已注册且账号正常
- **When**: 输入正确的邮箱和密码
- **Then**: 登录成功，跳转到首页

### AC2: 密码错误时提示
- **Given**: 用户已注册
- **When**: 输入错误的密码
- **Then**: 提示"邮箱或密码错误"

### AC3: 账号锁定时提示
- **Given**: 用户账号已被锁定
- **When**: 尝试登录
- **Then**: 提示"账号已锁定，请联系管理员"

### AC4: 连续错误锁定
- **Given**: 用户已连续 5 次输入错误密码
- **When**: 再次输入错误密码
- **Then**: 账号被锁定 30 分钟

---

## 业务规则

| 规则ID | 规则描述 |
|--------|---------|
| BR001 | 连续 5 次错误密码，锁定账号 30 分钟 |
| BR002 | 锁定后需等待或联系管理员解锁 |
| BR003 | 登录成功后重置错误计数 |

---

## 技术约束

| 约束类型 | 约束描述 |
|---------|---------|
| 安全 | 密码必须加密传输（HTTPS） |
| 安全 | 密码不能明文存储 |
| 性能 | 登录响应 < 500ms |

---

## 备注

- 支持记住登录状态（7 天）
- 需要记录登录日志（IP、时间）
```

## 四、验收标准编写规范

### 4.1 Given-When-Then 格式

```markdown
### AC{n}: {验收条件名称}
- **Given**: {前置条件}
- **When**: {用户行为}
- **Then**: {预期结果}
```

### 4.2 多个前置条件

```markdown
### AC1: xxx
- **Given**: {前置条件1}
- **And**: {前置条件2}
- **When**: {用户行为}
- **Then**: {预期结果}
```

### 4.3 多个预期结果

```markdown
### AC1: xxx
- **Given**: {前置条件}
- **When**: {用户行为}
- **Then**: {预期结果1}
- **And**: {预期结果2}
```

## 五、优先级定义

| 优先级 | 定义 | 说明 |
|--------|------|------|
| **Must** | 必须有 | 本次迭代必须完成 |
| **Should** | 应该有 | 本次迭代应该完成，可推迟 |
| **Could** | 可以有 | 本次迭代可以做，可省略 |
| **Won't** | 不做 | 本次迭代不做，记录为未来参考 |

---

## 六、故事点估算

| 点数 | 复杂度 | 工作量 |
|------|--------|--------|
| 1 | 极简单 | < 2 小时 |
| 2 | 简单 | 2-4 小时 |
| 3 | 中等 | 4-8 小时 |
| 5 | 复杂 | 1-2 天 |
| 8 | 很复杂 | 2-3 天 |
| 13 | 极复杂 | 3-5 天 |
