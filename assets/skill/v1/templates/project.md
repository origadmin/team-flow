2. 无法自动填充的字段 → 询问用户
3. 补充完整后继续

## 项目约定 (Project Conventions)

> 项目级统一规范，所有 AI 必须遵循。与错误无关，是项目本身的架构约定。

### URL / 路由约定

| 类型 | 前缀 | 示例 | 说明 |
|------|------|------|------|
| Admin 管理页面 | `/admin` | `/admin/users`, `/admin/settings` | 后台管理统一前缀 |
| API 接口 | `/api/v1` | `/api/v1/users`, `/api/v1/orders` | REST API 统一前缀 |
| 健康检查 | `/health` | `/health`, `/health/ready` | 服务健康状态 |
| 指标监控 | `/metrics` | `/metrics` | Prometheus 指标 |
| 静态资源 | `/static` | `/static/images/logo.png` | 静态文件 |

### 命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 数据库表 | 下划线命名，复数 | `user_profiles`, `order_items` |
| Go 结构体 | 驼峰命名 | `UserProfile`, `OrderItem` |
| API 端点 | 小写，连字符分隔 | `/api/v1/user-profiles` |
| 环境变量 | 大写，下划线分隔 | `DATABASE_URL`, `REDIS_HOST` |
| 配置文件 | 小写，点号分隔 | `app.config.yaml` |

### 模块边界约定

| 模块 | 职责边界 | 禁止行为 |
|------|---------|---------|
| `internal/service` | HTTP/gRPC 接口层 | 禁止直接访问数据库 |
| `internal/biz` | 业务逻辑层 | 禁止依赖具体存储实现 |
| `internal/data` | 数据访问层 | 禁止包含业务逻辑 |

### 错误码约定

| 范围 | 用途 |
|------|------|
| 1000-1999 | 通用错误（参数错误、权限不足等） |
| 2000-2999 | 用户模块错误 |
| 3000-3999 | 订单模块错误 |
| 9000-9999 | 系统级错误 |
