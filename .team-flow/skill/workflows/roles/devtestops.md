# DevTestOps 全流程质量保障 — v2 beads-native

> **适用**: 所有开发任务的质量门禁

---

## 核心原则

1. **核心链路必须验证** — 主流程跑不通不能提测
2. **高风险专项必须补充** — 触发条件命中时必须做
3. **提测准入有底线** — 基础项没过不进正式提测

---

## 执行流程

### Step 0：判断当前阶段

| 用户意图 | 对应阶段 |
|---------|---------|
| "分析需求" | 阶段 1 需求澄清 |
| "设计方案" | 阶段 2 方案与用例准备 |
| "写完了""自测" | 阶段 3 基础质量验证 |
| "联调""E2E" | 阶段 4 主链路验证 |
| "专项测试" | 阶段 5 专项与性能 |
| "提测" | 阶段 6 提测与回归 |
| "上线" | 阶段 7 上线与观察 |

### Step 3：基础质量验证

**判定变更类型**（读取 test-levels.md）：

```
变更类型判定：
├─ 纯逻辑调整    → 单元 + 模块 + 回归
├─ 接口改动      → + API 测试
├─ 跨模块改动    → + 集成测试
├─ 核心链路改动  → + E2E + 专项测试
└─ 高风险改动    → + 性能基准 + 回滚演练
```

- [ ] 单元测试全部通过（覆盖率 ≥ 80%）
- [ ] 无 lint/typecheck 错误

### Step 5：专项与性能

读取 specialized-tests.md，逐条匹配触发条件。

**后端 8 类专项**：E2E、接口/API、权限与安全、并发/幂等、数据一致性、异步任务、配置与兼容、回滚与可观测

**前端 10 类专项**：组件渲染、用户交互、Hook 逻辑、API 集成、路由守卫、响应式布局、可访问性、状态管理、国际化、主题

---

## beads 状态同步

```bash
# 提测时更新
bd update <id> --add-label phase:verify

# 提测准入通过
bd update <id> --add-label phase:review

# 上线
bd close <id> --reason "Released"
```
